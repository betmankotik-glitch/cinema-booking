# Cinema Booking System

Консольна система для перегляду фільмів та бронювання квитків у кінотеатрі на Python.

## Git

### Створені гілки та їх призначення
* **`master`** — головна робоча гілка проєкту.
* **`feature/movies`** — реалізація базового списку фільмів, додавання нових фільмів та перегляд інформації про них.
* **`feature/booking`** — функціонал вибору фільму, кількості квитків та бронювання.
* **`feature/cancel-booking`** — додавання функції скасування бронювання.
* **`feature/search`** — паралельна розробка функції пошуку фільмів за назвою.
* **`feature/favorites`** — паралельна розробка функції додавання фільмів до списку обраного.
* **`feature/menu`** та **`feature/menu-update`** — розробка двох різних варіантів головного меню програми для створення штучного merge-конфлікту.
* **`feature/statistics`** — реалізація модуля статистики (кількість доступних фільмів, заброньованих квитків та вільних місць) для практики `rebase`.
* **`feature/discount`** — додавання функції розрахунку знижки на квитки для практики `cherry-pick`.
* **`feature/temp-work`** — гілка для демонстрації роботи з тимчасовим сховищем `git stash`.

### Вирішення Merge-конфлікту
* **Де виник конфлікт:** У файлі `src/main.py` при злитті гілки `feature/menu-update` у гілку `master` (після попереднього злиття `feature/menu`).
* **Як його було вирішено:** Файл `src/main.py` було відредаговано вручну — обрано фінальний варіант меню, видалено маркери конфлікту (`<<<<<<<`, `=======`, `>>>>>>>`), після чого виконано `git add src/main.py` та завершено злиття комітом `dde6c51` (*Merge branch 'feature/menu-update'*).

### Практика Rebase
* **Де використовувався:** У гілці `feature/statistics`.
* **Процес:** Після створення комітів у гілці `feature/statistics` у головну гілку `master` було внесоно нові зміни (`277bd5d commit-master`). Для збереження лінійної історії було виконано `git rebase master`, що перенесло коміти гілки `feature/statistics` поверх останнього коміту `master`.

### Практика Cherry-pick
* **Де використовувався:** Перенесення конкретного коміту з гілки `feature/discount` у `master`.
* **Процес:** У гілці `feature/discount` було створено окремий коміт `d9cdb04` (*Add ticket discount*). Переключившись на `master`, виконано команду `git cherry-pick d9cdb04`, що перенесло зміни у головну гілку у вигляді коміту `e11433b`.

### Практика Stash
* **Де використовувався:** У гілці `feature/temp-work`.
* **Процес:** Під час розробки нових змін було перевірено стан `git status`, після чого незакомічені зміни були тимчасово відкладені командою `git stash`. Після перемикання між гілками та виконання необхідної роботи зміни були успішно відновлені командою `git stash pop`.
